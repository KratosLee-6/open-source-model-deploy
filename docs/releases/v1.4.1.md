## ❌ v1.3.0 错在哪

### 错误 1：接口路径

我在 v1.2.0/v1.3.0 里写的是 `/v1/decide`。真机上：

```
$ curl -X POST localhost:8000/v1/decide -d '{...}'
{"detail":"Not Found"}
```

`/v1/decide` 是 JEV 的**图像/多模态**接口，需要另起 `vl/serve.sh`（含 vision encoder）。
纯 `vllm serve` 上没有这个路由。

**真正的文本决策入口是 `/v1/completions`**，用 `allowed_token_ids` + `logprobs`。

### 错误 2：`model` 字段

填基座名 `autotrust/JEV-9B` → 走 System 2，返回**自由生成的文本**，不是概率。
必须填 LoRA 名 **`jev-decision`**。

### 错误 3：缺 prompt 模板

JEV 要求严格的 bare-v1 模板，choice 选项要带 `A) ` 前缀：

```
[kind] choice
[state] 合同文本…
[question] 风险等级
[options]
A) 低
B) 中
C) 高
[decision]:
```

随便构造 body 模型不知道在回答什么。

### 错误 4：以为服务端返回概率

服务端返回的是**未校准 logits**。校准在客户端做：

```
z_i = (logprob(verbalizer_i) + bias[i]) / T[kind]
p   = softmax(z)
```

`bias` 24 个（±0.006 量级）在 `adapter_vllm/decision_head.json`，
`T` 在 `calibration.json`（noul 1.0022 / choice 0.9840 / score 1.0122）。

## 🐛 顺带抓到的静默坑：tokenizer 缺失

`hf download` 时 `huggingface_hub` 依赖的 `httpx2` 有段错误：

```
File "httpx2/_decoders.py", line 191, in decode
    decompressed = self._decompress(data, output_buffer_limit=output_buffer_limit)
TypeError: process() takes no keyword arguments
```

后果：**`tokenizer.json` 静默缺失**，模型 17.9GB 全部下齐了，唯独少了 tokenizer。

表现极具迷惑性 —— 服务能起来，`/v1/models` 正常，但**所有请求 400**：

```
{"error": {"message": "The decoder prompt cannot be empty"}}
```

因为 tokenizer 把任何文本 encode 成 **0 个 token**：

```
>>> AutoTokenizer.from_pretrained(...).encode("Hello", add_special_tokens=False)
[]                      # ← 空
>>> tokenizer.decode([3721])
''                      # ← verbalizer 也解不出来
```

**修法**：绕过 huggingface_hub，用 curl 单独补：

```bash
curl -sL -o tokenizer.json \
  "https://hf-mirror.com/autotrust/JEV-9B/resolve/main/tokenizer.json"
```

补完立刻正常：

```
>>> verify_tokenizer()
'Hello' -> 1 token
verbalizer_ids 解码: ['false','true','0','1','2','3','4','5','A',...,'P']
```

**这条已写进配方的 notes 和 v1.3.0+ 的下载检查步骤。**
