# v1.4.3 — 分类启发式修正（W3）

> 修的是**自动收录**这一环：周更的 `auto_fetch_models.py` 之前会把候选模型
> 分错类，分错的条目一旦入库就成了错数据 —— 而且没人会发现，因为 lint
> 当时**不做分类白名单校验**。

**日期**：2026-10-31
**模型数**：168（不变）

---

## 修了什么

### 1. 返回了不存在的分类（数据污染源）

`CATEGORY_BY_TAG` 里写着一个 `"image-generation"`，但 `KNOWN_MODELS` 里
**根本没有这一类**。于是 `guess_category()` 能返回它，生成出来的条目
lint 也抓不到（lint 没做白名单校验），只能等人工 review 才发现。

现在：

- `VALID_CATEGORIES` 把 9 大类显式列成白名单
- `guess_category()` 的返回值保证落在白名单内
- `CATEGORY_BY_TAG` 里的 `text-to-image` 改为归 `vision`（文生图没有独立类）

### 2. `EleutherAI/pythia-160m` 被判成 `international-dense`

160M 的小模型标成 dense，语义是"需要大机器" —— 会误导部署决策。

根因是 edge/dense 的判定靠**名称正则抠参数量**，而 `pythia-160m` 的
`160m` 不是 `B` 结尾（是 M），正则只认 `B`，抠不到就走了错误的分支。

现在按 `_effective_b_from_name()` 统一处理（`M` 也认），且 MoE 用**激活参**
判定（与显存估算口径一致）。

### 3. `stabilityai/*` 落到兜底 → `domestic-general`

`stabilityai`（Stability AI，美国）原本既不在国内 namespace 列表、也不在
国际 namespace 列表里，最后掉进兜底被判成国内通用模型。

现在补全了 namespace 表（国际侧新增 `openai` / `openbmb` / `lmms-lab`）。

### 4. 死代码

```python
return "domestic-reasoning" if any(...) else "domestic-reasoning"
```

两个分支一样，条件表达式没有意义。已删。

### 5. 功能类判定顺序反了

embedding / reranker / code / vision 这类**功能分类**必须**优先于** namespace
判断。原顺序下 `BAAI/bge-m3`（BAAI 是国内 namespace）会被判成国内通用模型，
而它的真值是 embedding。

现在顺序是：功能类 → 推理类 → namespace → 兜底。

补齐的功能识别：

| 识别方式 | 例子 |
|---|---|
| `bge-*` 前缀 | `BAAI/bge-m3`（名字里没有 "embed"）|
| `sentence-transformers` 整库 | `all-MiniLM-L6-v2` / `paraphrase-*` |
| 模型名含视觉标记 | `InternVL*` / `MiniCPM-V*` / `llava` / `Florence-2` / `Cosmos` / `diffusiongemma` / `idefics` / `paligemma` / `pixtral` / `mllama` |

## 一条真值错误

`nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16` 原分类是
**`domestic-general`** —— NVIDIA 是美国公司，标成国内明显是错标
（同系列的 `nemotron-3-nano-30b-a3b` 就标的 `international-edge`）。

已改为 `international-edge`。

---

## 回归测试：用 169 条真实数据当基准

新增 `tests/test_category_heuristic.py`（35 个测试）。

核心断言不是手写几条期望值，而是**拿现有 `KNOWN_MODELS` 的 169 条人工
分类当基准**，让新启发式跑一遍已有模型，断言分类不变 —— 基准来自
review 过 9 个月的数据，不是拍脑袋定的。

另外 6 条人工有意与通用规则不同的条目，进了显式例外表
（`CATEGORY_OVERRIDES`），并在代码里写明理由：

| 条目 | 分类 | 为什么是例外 |
|---|---|---|
| `Llama-4-Maverick-17B-128E` | dense | 旗舰模型（激活 17B 但总参 402B）|
| `Llama-4-Scout-17B-16E` | dense | 同上（总参 108.6B）|
| `Mistral-Large-Instruct-2407` | dense | 名字里没有参数量，按家族定位 |
| `Mistral-Small-3` | dense | 同上（24B）|
| `Nemotron-3-Super-120B-A12B` | dense | 总参 123.6B 归 dense（虽激活仅 12B）|
| `gemma-2-9b-it` | dense | gemma-2 家族整体归 dense（gemma-3-9b 是 edge）|

## 对外价值

这套分类启发式现在可以稳定地给外部消费方用 —— 比如给 Hermes 官方
的 Local Models catalog 提供候选模型（详见
[hermes-agent#147273](https://github.com/NousResearch/hermes-agent/issues/147273)）。

分类准确是那件事的前提：**分错类的条目进了 catalog 就是错数据**，
而 catalog 的使用者（本地模型部署者）会照着它做部署决策。
