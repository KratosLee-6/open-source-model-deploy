## 🧹 README 数字自动化（治「截图会说谎」的老毛病）

以前每加一批模型，README 里要手改十几处数字（在架数 / 分类分布 / 显存筛选数 /
detect 可部署数 / lint 首行），漏一处就变成「README 说 137、代码跑出 169」。

新增 `scripts/sync_readme_numbers.py`：

```bash
python scripts/sync_readme_numbers.py --apply
```

它读**代码真实输出**，把 README 和 `check_readme_facts.py` 的 `EXPECT_*` 常量一起改，
改完自动重跑校验。这次 v1.1.1 就是这么把 16 项失败收敛到 0。

## ⚠️ 已知限制

1. **JEV 系模型的 `size_b` 取 HF `safetensors.total`**，是底座权重规模；
   实际部署还要叠加 LoRA adapter（几十 MB 到 100MB 级）。
2. **`juspay/xor` 标 35.11B 但仓库用 SGLang 部署**，本工具默认给 vLLM 命令，需手工换。
3. **`openjev/openjev` 是 CC BY-NC 4.0**（非商用），商用前必须换模型或单独授权。
4. **显存筛选数与运行机器绑定** —— 换机器跑 `check_readme_facts.py` 必然失败，
   这是设计（数字本来就该跟着机器变），改完记得 `sync_readme_numbers.py --apply`。
